# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Picto is a static React SPA for building visual schedules (ordered lists of pictograms). **It's used mainly on phones (iPhone and Android)**, so design and test phone-first. See README.md for what the app does from the user's side. Stack: Vite, React 19, MUI 9 (styling via `sx`, no `makeStyles`), React Router 8 (declarative `<Routes>`), Vitest + Testing Library.

## Commands

**Never install anything on the host or run `npm`/`node`/`npx` there.** All tooling runs in Docker:

```
docker compose up dev                                   # Vite dev server, http://localhost:3000 (runs npm install first)
docker compose run --rm dev npm test                    # all tests, once
docker compose run --rm dev npx vitest run -t "reorders"  # single test by name
docker compose run --rm dev npm run lint
docker compose run --rm dev npm run build
docker compose up --build app                           # prod nginx image, http://localhost:8090
docker compose build app && docker compose run --rm e2e # Playwright e2e against the prod image
docker compose run --rm e2e npx playwright test -g "bin"  # single e2e test by name
docker compose run --rm e2e npx playwright test --project iphone  # one device: desktop | android | iphone
```
Host ports default to 3000 (dev) and 8090 (app); 5173 and 8080 are used by other projects on this machine; override them with `PICTO_DEV_PORT` and `PICTO_PORT`. When checking that a port serves Picto, look for `<title>Picto</title>`: other Vite apps also serve `/src/main.jsx`. `node_modules` is a named volume; the `dev` stage of the `Dockerfile` pre-creates it owned by uid 1000 so files written to the bind mount (such as `package-lock.json`) stay user-owned.

**`overrides.minimatch` in `package.json`** forces `minimatch` ^11.0.8 under ESLint 10 to fix GHSA-g3hv-75wg-m249 (DoS, dev-only; ESLint still asks for ^10). Remove it once ESLint depends on a patched `minimatch`, then check `npm audit`. After changing it, confirm ESLint's file matching with `npx eslint --print-config <file>`. npm doesn't run `core-js`'s postinstall (a funding banner, via jsPDF → canvg); that's intended.

**Production serving (`nginx.conf`, `Dockerfile`):** the build stage pre-compresses text files with `gzip -9 -k` and nginx serves them with `gzip_static` (plus on-the-fly gzip as a fallback). The main script is 758 KB raw but about 233 KB over the wire. Caching: `/assets/` (hashed names) is immutable for a year; it uses `^~` so the icon regex location can't override it. `index.html`, every SPA route (served `index.html` via `try_files`) and `manifest.json` are `no-cache`, so updates reach users at once. Icons in `public/` cache for a day. Use only `add_header` for `Cache-Control`; `expires` adds a second header. `e2e/server.spec.js` checks all of this.

## Architecture

- **No backend.** Search calls the public, CORS-enabled ARASAAC API directly from the browser (`src/hooks/useArasaacSearch.js`). The API answers **404 with `[]`** when nothing matches, which is treated as "no results". Image URLs are built from the pictogram id (`static.arasaac.org/pictograms/{id}/{id}_{res}.png`).
- **Routes** (`src/SiteMap.js`): `/` is the collections list (`pages/CollectionList.jsx`), `/sequence/:id` is one sequence (`pages/Sequence.jsx`), plus `/settings` and `/about`. Unknown paths render the list.
- **Privacy statement** (About page, `privacy.*` strings) promises that user data stays on the device and that only search words go to ARASAAC and Commons. `e2e/privacy.spec.js` enforces it: a full session may only contact the app and `static.arasaac.org`, with no request bodies or non-GET methods, and searches send only the word. Any new network call, storage or third party must keep both the statement and that test true.
- **Images** (`src/images/`): a pictogram's `img` is either a web URL (ARASAAC, Wikimedia Commons) or `"local:<id>"` for an own image. Own images are kept in IndexedDB (`imageStore.js`, db `picto`, store `images`) as `{ type, data: ArrayBuffer }`, not as Blobs (older iOS Safari couldn't keep Blobs in IndexedDB). Anything that shows or prints an image must resolve it: `useImageSrc(img)` in components, and `makePdf`'s `imageBlob()` for the PDF. Never use `p.img` as a `src` directly. Unused own images are deleted once per app start (`CollectionsProvider`), not on every change, so undoing a delete still works. Cropping own images: `OwnImageForm` uses `react-easy-crop` (drag; pinch, wheel or MUI slider to zoom 1–4×; square aspect, `objectFit="contain"`). `onCropComplete` gives the area in image pixels, which `processImage(file, { crop, area })` cuts out. It never upscales, falls back to a centred square without an area, and keeps the whole image when `crop` is false; output is at most 800 px, JPEG. That needs a real canvas, so unit tests mock it. `e2e/crop.spec.js` checks real output with a red|blue 1200×600 PNG (generated at `deviceScaleFactor: 1`; phone profiles are 2–3×) by sampling the stored image's edge colours: mouse drag on desktop, CDP one-finger drag and two-finger pinch on Android, slider everywhere. Step the MUI slider with ArrowRight; PageUp jumps further than one might expect. Commons (`useCommonsSearch.js`): `origin=*` makes the API work from the browser, and upload.wikimedia.org sends CORS. **Commons only serves standard thumbnail widths** (330, 500, 960, ...) and answers other widths with 400. The API is asked for 960 (stored on the card) and the grid swaps in `/330px-`. Commons pictograms carry `credit: { author, license, url }`, listed on the About page.
- **Persistence:** `CollectionsProvider` (`src/context/`, wrapped around the whole app) is the single source of truth, read via `useCollections()`. It stores `localStorage["collections"]` as `{ collections: [{ id, name, pictograms: [{ id, img, text, credit? }] }] }`. On first load, if that key is empty, the pre-0.3 single schedule in `localStorage["pictograms"]` (also the v0.1 Flaticon-era format) is migrated into a sequence named "My sequence". The legacy key is left untouched. Tests cover the migration. All ids are uuids; pictogram ids are not ARASAAC ids, so the same pictogram can appear twice.
- **Dialogs:** MUI `Dialog` unmounts its children when closed, so form state lives in an inner component to reset on reopen (`NameDialog`, `PictoAdder`). While a dialog is closing, the page behind it is `aria-hidden`, so tests must wait for the dialog to disappear before querying by role.
- **i18n:** a small homegrown layer in `src/i18n/`. Every UI string lives in `strings.js` (`da` and `en`, with `{param}` placeholders; plurals are functions). Components call `const t = useT()`; never hard-code UI text. The language is stored in `localStorage["language"]` and defaults to `"da"`. `LanguageProvider` sits outside `CollectionsProvider`, so the migrated sequence gets a localized name.
- **Search locales:** `SEARCH_LOCALES` in `strings.js` maps the UI language to the ARASAAC locales tried in order. ARASAAC *accepts* `da` but has no Danish keywords (every search is empty, verified 2026-11), so Danish searches `nb` and then `en`. `useArasaacSearch(query, locales)` returns the `locale` that produced results. The fallback makes the browser log a 404 for the first locale; that's ARASAAC's normal "no matches" answer.
- **Edit lock:** `EditLockProvider`/`useEditLock()` (`src/context/editLock*`) holds `locked`, persisted in `localStorage["editLocked"]`, and toggled by the padlock in `TopBar` (a toggle button: constant name plus `aria-pressed`). Pages honour it themselves. `CollectionList` hides the rename, delete and new controls. `Sequence` renders plain `Pictogram`s, with no `DndContext`, adder, bin or label editor, instead of `SortablePictograms`. Settings and About ignore it. Any new editing UI must check `locked`.
- **Preferences:** `PreferencesProvider`/`usePreferences()` holds display settings in `localStorage["preferences"]`. Today that's only `binSide` (`"left"` by default, or `"right"`), used by `TrashBin`, which exposes it as `data-side` for tests. Stored values are validated, and unknown ones fall back to the defaults. Put new settings here rather than in new top-level keys.
- **Drag and drop** (`components/SortablePictograms.jsx`, `TrashBin.jsx`) uses `@dnd-kit/core` and `sortable`. Sensors: mouse after 8px, touch after a 250ms press (so swipes still scroll), keyboard. A custom collision detection picks the bin only when the *pointer* is inside it, otherwise the closest card. Keyboard drags have no pointer, so the bin is disabled for them and Delete on the focused card deletes instead. The bin uses `Fade` rather than a scaling transition because dnd-kit measures droppables when the drag starts. Events inside the label/editor call `stopPropagation` so they don't start drags (Space would trigger the keyboard sensor). Screen-reader announcements are translated (`dnd.*` keys).
- **Printing** (`pages/PrintSequence.jsx`, `src/print/`): `sheetLayout()` in `src/print/layout.js` is the single source of the A4 layout in mm, including the split into pages. The on-screen sheet (CSS, real mm sizes, scaled with a transform to fit the screen) and the PDF (`makePdf.js`, jsPDF loaded with a dynamic `import()` so it's a separate chunk) both use it, so they must stay in sync. Print CSS sets `@page { size: A4 <orientation>; margin: 0 }`, hides `.MuiAppBar-root` and `.no-print`, and undoes the scaling. The preview's wrapper must clip on screen (WebKit counts the untransformed width and scrolls sideways) and starts from `window.innerWidth`, not 0. The PDF fetches images with CORS into a canvas, so SVG works and nothing is tainted. Keep `compress: true` and `"FAST"` image compression (otherwise about 1 MB per pictogram). `savePdf()` uses `navigator.share` on touch devices and falls back to a download. Print settings live in preferences: `printOrientation` (paper), `printTitle`, `printDirection` (`horizontal` = rows read left to right; `vertical` = columns read top to bottom, then rightwards), `printPerLine` (pictograms per row or column; `null` = auto) and `printWrap` (default off). `layout.js` works in *lines* (a row or a column, depending on direction). A line fills the page in its direction. Without wrap each page holds one line; with wrap, lines stack side by side until the page is full, and the rest continue on further pages. Cells are placed absolutely in mm, the same positions the PDF uses. `sheetLayout(n, options)` takes the same options object the page passes to `savePdf`. Auto picks the number per line that gives the fewest pages, then the largest cells. The preview is a horizontal scroll-snap carousel (`.print-pages` → `.print-slide` → `.print-sheet` → `.print-page`). Each sheet is scaled to fit the width and the height left below the desk (at least 45% of the window). Print CSS turns the carousel back into a column of pages with `break-after: page`. Tests use `data-pages`, `page-indicator` and `per-line-value`. Android e2e swipes the carousel with CDP touch events.
- **Phone checks** (`e2e/phone.spec.js`, run on the `iphone` project, iPhone SE (3rd gen) in WebKit, and on `android`, a Pixel 7): no horizontal scroll on any screen, every visible button at least 44×44 (the theme in `main.jsx` enforces this for MUI buttons), and row text never under its action buttons. Add new screens to these checks. The collections row is a plain flex row, not MUI's `secondaryAction`, whose absolute positioning let long names run under the icons.
- **Drag can't be tested in jsdom** (all rects are zero), so it's covered by Playwright in `e2e/`. The `e2e` service uses `mcr.microsoft.com/playwright:v<ver>-noble`, which must match the exact `@playwright/test` version in `package.json`. ARASAAC is stubbed with `page.route`. Touch drags are sent as raw CDP `Input.dispatchTouchEvent`s, since Playwright has no touch-drag API. The browser reaches the prod container as `picto-web`, not `app`: Chrome forces HTTPS for `app` (an HSTS-preloaded TLD). Keyboard e2e steps sync on dnd-kit's live-region text, not timeouts.
- **Tests fail on `console.error`** (`src/test/setup.js`), which catches invalid-prop warnings, such as props removed in MUI 9 like `Typography paragraph`. Tests pin English via `renderApp(path, { language })`; pass `{ language: null }` to exercise the Danish default.
- **Context file split:** contexts and hooks live in lower-case `*Context.js` files and providers in `*Provider.jsx`, because `react-refresh/only-export-components` forbids mixing them.
- **App version:** injected from `package.json` as the `__APP_VERSION__` global via `define` in `vite.config.js`, and re-exported as `AppVersion` from `src/SiteMap.js`.
- **Lint rules that bite:** `react-hooks/set-state-in-effect` forbids synchronous `setState` in effect bodies. That's why `useArasaacSearch` derives `loading` from a result tagged with its request key.
